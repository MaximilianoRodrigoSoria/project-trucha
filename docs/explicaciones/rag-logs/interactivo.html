El RAG de logs de project-trucha 🕵️

Explicación interactiva para que de verdad se entienda — elige tu nivel para empezar.
El evador (20 segundos): project-trucha es un traductor universal de registros. Le tiras cualquier log (prolijo o garabateado), lo lee, le arma la historia (traza), lo guarda en dos archivos (uno por "significado", otro por "causa y efecto") y después responde preguntas buscando en ambos — todo sin internet ni claves.

En menos de 3 frases

El sistema lee cualquier log por desprolijo que sea, arma un expediente cronológico resumido (la traza), lo guarda en dos archivos (uno por significado parecido y otro por causa-efecto), y al preguntarle busca en ambos y responde citando sus pruebas.

La clave: el mismo incidente bien o mal escrito produce el mismo significado, y el sistema marca la confianza de cada dato.

Las 3 fases (para recordar el flujo)

FASE 1 · Ingesta (pasos 0–2) parsear → traza → resumen
FASE 2 · Almacén dual (pasos 3–4) vector + grafo causal
FASE 3 · Respuesta (pasos 5–6) búsqueda híbrida → respuesta LLM

La metáfora ancla: el detective forense

Imaginá una mesada de un archivo policial. Hay papeles prolijos (declaraciones legibles, con fecha, cada uno señalando "esto pasó porque esto") y papeles garabateados (anotaciones al margen, sin año, con abreviaturas [WARN] api-gw :: payment_failed (trc=reqId_88)).

El detective forense (el sistema):

  1. Lee cada papel aunque esté garabateado → transcribe a una ficha normalizada.
  2. Junta las fichas del mismo incidente en un expediente cronológico (la traza) y escribe un resumen narrativo ("Pago rechazado del usuario u_7f por $99").
  3. Guarda el resumen en dos archivos: uno por "parecido de significado" (vector), otro por "causa y efecto" (grafo).
  4. Al preguntarle, busca en ambos y responde con las pruebas citadas.
Prolijo (clean) — declaración legible
{"event_id":"e1","caused_by":null,"service":"api-gw","level":"WARN","message":"payment_failed","user_id":"u_7f"}

Causalidad explícita → confianza 1.0

Garabateado (repaired) — anotación al margen
[WARN] api-gw :: payment_failed (user u_7f, trc=reqId_88)

Causalidad inferida → confianza 0.6

El mismo incidente, el mismo significado — distinta confianza marcada.

Fase 1 · Ingesta

Paso 0 · Cascada de parsers — parse.py

json.loads → SLOPPY_RE → BARE_RE → STACK_RE → SYSLOG_RE → _from_logfmt()
(limpio)   (comilla simple)  ([LEVEL] svc :: msg)  (stack pegado)  (syslog)   (logfmt)
Si nada matchea → la línea se descarta (None).

parse_timestamp() normaliza a ISO 8601 UTC; si falta año/hora completa con la fecha de ingesta y marca timestamp_inferred=true. parse_file() degraada a "low_confidence" los reparados sin trace_id.

Pasos 1–2 · Traza + resumen — trace.py

  • traces_from_events() agrupa por trace_id y ordena por timestamp.
  • _assign_fallback_traces(): sin trace_id → se agrupa por usuario+servicio en 2 s → "low_confidence".
  • _assign_synthetic_event_ids(): event_id determinista (blake2b) → MERGE idempotente.
  • _resolved_caused_by(): causalidad explícita 1.0 o inferida 0.6; toda-inferida → "repaired".
  • _worst_quality(): gana el peor (clean>repaired>low_confidence).
  • build_summary(): el artefacto que se vectoriza.

Fase 2 · Almacenamiento dual

Paso 3 · Embedding local determinista — embed/local.py

for token in tokens:
    digest = blake2b(token.encode(), digest_size=16).digest()
    index  = int.from_bytes(digest[:8], "big") % 64   # bucket
    sign   = 1.0 if digest[8] & 1 else -1.0           # signo
    vector[index] += sign
¡Ahá! (emoción/contraste): nada sale de tu máquina — es el sello local-first. 64 dimensiones, sin dependencias, determinista → tests predecibles.

Se persiste en TraceModel (tabla traces, único por (source_path, trace_id) → idempotente) con índice HNSW de coseno (migración 0002_traces.py).

Paso 4 · Grafo causal — graph/

Funciones puras en build.py que devuelven Cypher (testeables sin Neo4j):

  • Nodos: Trace, LogEvent, y por PUT Service/User/PaymentID.
  • Relaciones: CAUSED_BY (confidence 1.0/0.6), PART_OF, EMITTED_BY, INVOLVES.
  • GraphClient.causal_chain() recupera la cadena en orden temporal con la confianza.

Fase 3 · Respuesta

Paso 5 · Búsqueda híbrida — services.py

  1. Semántica: embedding de la pregunta → coseno en traces.embedding (top-k).
  2. Causal: con esos ids → causal_chain() del grafo (si hay).
  3. Marca: low_confidence = source_quality != "clean", vector_score, cadena.
Degradación segura: si el grafo falla, sigue devolviendo trazas con cadena vacía — la búsqueda no se rompe por el grafo (services.py:254).

Paso 6 · Capa de respuesta — answer.py + llm/

answer_logs(): recupera evidencia → arma prompt con _build_prompt()/_format_evidence() (marcar [INFERIDA]/[REPARADA] y citar traza) → get_provider() → ""→NoneProvider, openai, anthropic.

NoneProvider = fallback determinista sin API key (local-first). Resultado: {question, answer, provider, results}.

El porqué del diseño

  • Por qué dos magacenes: el vector recuerda "parecido", no "causa". El operador que diagnostica quiere la cadena causal; cada magacén optimiza un tipo de pregunta (híbrido).
  • Local-first / sin API keys: probá y enseñá siempre, sin credenciales; determinismo para tests predecibles.
  • El hilo de confianza (source_quality): el sistema es honesto: etiqueta clean/repaired/low_confidence y se lo comunica al LLM. Observabilidad de la confianza.
  • Trade-off: embeddings locales de 64d pierden matiz semántico, pero son reproducibles, baratos y sin red — elección deliberada para un RAG didáctico.
  • Errores comunes: confundir traza con log; creer que el grafo es obligatorio (degradación segura: funciona solo con vector); olvidar que source_quality viaja de punta a punta.
  • Mapeo general: es un RAG estándar (documento → chunks → embeddings → búsqueda → LLM) con un segundo recuperador causal (Neo4j) que enriquece la evidencia.
Recencia (cierre): volvemos al mensaje del inicio — un traductor universal que convierte cualquier log en historia, la guarda de dos formas y responde citando pruebas, siendo honesto sobre la confianza del dato. Eso es el RAG de logs.
